# Sheet Views Map — панель «Виды на листах»

Небольшой плагин для Revit: собственная вкладка на ленте с кнопкой, которая
открывает **отдельное окно поверх Revit** (как Assembling Manager).
В окне — таблица всех номеров видов с галочками, поиском и кнопками.
Цвета: тёмно-зелёный фон, розовые акценты.

| № | | № вида | Название вида | Листы (номер — название) |
|---|---|---|---|---|
| 1 | ☐ | A-101 | План 1-го этажа | A-12; A-15 |
| 2 | ☑ | A-201 | Разрез 1-1 | A-13 |

| № вида | Название вида | Листы (номер — название) | Листов |
|---|---|---|---|
| А-201 | План 1-го этажа | А-101 — Планы этажей 1 | 1 |
| А-301 | Разрез 1-1 | А-102 — Разрезы; А-205 — Узлы | 2 |

Двойной щелчок по строке открывает нужный лист в Revit.

---

## 1. Требования

- **Revit 2021, 2022 или 2023** (скрипт собирает под те версии, которые установлены)
- **.NET SDK 8** — <https://dotnet.microsoft.com/download/dotnet/8.0>
- Windows

Visual Studio **не нужна**: VSCode и `dotnet build` достаточно.
(про отладку — раздел 6)

---

## 2. Установка

1. Откройте папку `SheetViewsMap` на рабочем столе.
2. Дважды щёлкните **`build.cmd`**.
3. Дождитесь сообщения `Готово. Собрано версий: N`.
4. **Перезапустите Revit.**

Готово. На ленте Revit (рядом с «Архитектура», «Конструкция» и т. д.)
появится вкладка **Sheet Views Map** с кнопкой **«Открыть окно»**.

Кнопка открывает отдельное окно поверх всех окон (в том числе поверх Revit).
Повторное нажатие кнопки — закрывает окно. Положение и размер запоминаются.

### Где что настраивается

Названия вкладки, группы, кнопки и панели заданы константами
в начале файла `src\Shared\App.cs`:

```csharp
internal const string WindowTitle         = "Виды на листах";
internal const string RibbonTabName       = "Sheet Views Map";
internal const string RibbonPanelName     = "Виды на листах";
internal const string RibbonButtonText    = "Открыть окно";
```

### Что делает `build.cmd`

Для каждой установленной версии Revit:

1. Собирает `src\Revit<год>\SheetViewsMap<год>.csproj`.
2. Копирует готовую DLL в `%LOCALAPPDATA%\SheetViewsMap\<год>\`.
3. Создаёт `%APPDATA%\Autodesk\Revit\Addins\<год>\SheetViewsMap.addin`.

DLL намеренно копируется **в отдельную папку**, а не остаётся в `bin\`:
если держать её в папке проекта, Revit может заблокировать файл и правки
перестанут подхватываться.

## 3. Как пользоваться

| Действие | Как |
|---|---|
| Открыть / закрыть окно | Вкладка **Sheet Views Map** → кнопка **«Открыть окно»** |
| Перечитать данные | Кнопка **«Обновить»** (при первом открытии окна данные грузятся сами) |
| Отметить строки | Галочки; «Выбрать все» отмечает все видимые строки |
| Выбрать комплект листов | Список **«Комплект»** — берётся параметр листа `ADSK_Штамп Раздел проекта` |
| Найти листы с плохой нумерацией | Кнопки **«Проблемные»** / **«Гудные»** (взаимоисключающие, повторное нажатие снимает фильтр) |
| Открыть лист | «Открыть лист» — если отмечено несколько строк, листы открываются **по очереди** с паузой 0.9 с |
| Отфильтровать по номеру вида | Поле **«№ вида»** — сначала точное совпадение (A-201), если таких нет, то все номера, начинающиеся с введённого (A-2 → A-201, A-202) |
| Отфильтровать по номеру вида | Поле **«№ вида»** — сначала точное совпадение (A-201), если таких нет, то все номера, начинающиеся с введённого (A-2 → A-201, A-202) |
| Найти что угодно | Поле **«Поиск»** — подстрока в номере вида, названии вида или списке листов |
| Копировать в Excel | «Копировать» — отмеченные строки (или все видимые) с разделением по столбцам |
| Перейти на лист | Двойной щелчок по строке или «Открыть лист» |
| Выбрать лист | Если вид на нескольких листах — появится список, выберите нужный |

В строке снизу видно имя документа, количество листов и количество видов на них.

### Поведение окна

- Окно **принадлежит Revit** (`Window.Owner`): всегда над ним, но под другими
  программами. Вместе с Revit перемещается и сворачивается — это делает сама
  Windows, отдельного кода не нужно.
- Положение и размер сохраняются в `%LOCALAPPDATA%\SheetViewsMap\window.ini`.
- Если в настройках координаты с несуществующего монитора — окно открывается
  по центру окна Revit.
- Не появляется в панели задач: только вкладка на ленте Revit и само окно.

### Цвета

Палитра задана в `src\Shared\Theme.cs`, меняется в одном месте:

| Кисть | Цвет | Где |
|---|---|---|
| `Background` | `#0E3B33` | фон окна и строк |
| `Surface` | `#14483E` | поле поиска, обычные кнопки |
| `Accent` | `#F2C1D1` | главная кнопка, отмеченные строки, номера листов |
| `Text` | `#ECD8E0` | текст в таблице |
| `TextMuted` | `#86AFA2` | подписи и статус |

Цвет текста в столбцах «№», «№ вида» и «Название вида»: обычный — светло-розовый,
на отмеченной галочкой строке — тёмно-зелёный.

Столбец «Листы» ведёт себя иначе: зелёным (цветом фона) становятся **только
знак ⚠ и номер рядом с ним** — то есть только проблемные листы. Остальные
номера остаются розовыми. Условий сразу два (лист проблемный + строка
отмечена), поэтому используется `MultiDataTrigger` — см.
`ProblemOnCheckedTrigger()` в `SheetMapPane.cs`.

Размеры шрифта задаются константами в том же файле: `FontCell` (таблица),
`FontUi` (поля, кнопки), `FontSmall` (подписи, статус).

Кнопки плоские: обычные — тёмно-зелёные с розовым текстом, главная
(«Открыть лист») — розовая с тёмно-зелёным текстом. У кнопок-переключателей
«Проблемные» / «Гудные» включённое состояние — розовая заливка.
Иконка кнопки на ленте — объёмный плюс из двух скруглённых прямоугольников,
рисуется кодом в `Theme.CreatePlusIcon()`.

> **Осторожно:** не называйте поля в классе `Theme` именами `Border`, `Grid`,
> `Visibility`. Такое поле перекроет одноимённый тип WPF, и появится невнятная
> ошибка вроде `"Brush" не содержит определения "BackgroundProperty"`.
> Раньше с этим сталкивались уже дважды — в `SheetMapPane` и в `Theme`.

### Поиск листов с плохой нумерацией разрезов

Главная проверка плагина: находит листы, где нумерация **разрезов**
(`ViewType.Section`) начинается не с единицы.

| Лист | Виды на нём | SectionStart | Проблемный |
|---|---|---|---|
| A-101 | 3Д, план №1, разрезы №5 и №6 | 5 | **да** |
| A-102 | 3Д, план №11, разрезы №1 и №2 | 1 | нет |
| A-103 | 3Д, план №1 (без разрезов) | 0 | нет |

Номер вида разбирается как число в конце строки: `5` → 5, `Р-12` → 12,
`А-1.1` → 1. Номера, не заканчивающиеся цифрой (`3D`, `АВТ`),
номером не считаются.

Проблемные листы помечаются знаком **⚠** прямо в столбце «Листы».
Чтобы значки стояли по одной вертикальной линии, каждый номер листа выводится
в слоте фиксированной ширины (`SheetNumberSlotWidth` в `SheetMapPane.cs`),
а место под знак зарезервировано всегда — даже для корректных листов.

Столбец «Листы» выводит не строку, а список `SheetRefs`, поэтому очистка от
повторов делается именно в списке — иначе один и тот же номер печатался бы
в ячейке несколько раз. Листы с одинаковым номером схлопываются в один
(сравнение регистронезависимое). Если среди них есть проблемный, знак **⚠**
остаётся — см. `MergeSheetRefs()` в `SheetMapReader.cs`.

### Комплект листов

Список «Комплект» берётся из параметра `ADSK_Штамп Раздел проекта`.
Поиск параметра идёт в три шага, потому что название может отличаться:

1. Точное совпадение имени.
2. То же имя без префикса `ADSK_`.
3. Любой параметр листа, в названии которого есть и «штамп», и «раздел».

Значение читается независимо от типа: строка, ссылка на элемент (тогда берётся
имя элемента) или целое число.

Если комплекты не нашлись, в строке статуса появится подсказка:

```
... |  Комплекты не найдены: на листах пусто или нет параметра «ADSK_Штамп Раздел проекта»
```

Тогда поправьте константу `SetParameterName` в `SheetMapReader.cs`.

### Почему листы открываются по очереди

Revit показывает **только один активный вид** в документе, а открыть лист в
отдельном окне через API нельзя — в `Autodesk.Revit.UI` нет такого метода
(проверяли: `UIApplication` умеет открывать только документы, а `UIView` —
только закрывать и масштабировать уже открытые виды).

Поэтому «Открыть лист» при нескольких отмеченных строках ставит все листы
в очередь и открывает их с паузой 0.9 с: все листы будут просмотрены и
попадут в «Недавние виды», но в результате открыт останется последний.
Внизу окна показывается прогресс: «Открываю листы: 2 из 5».

### Что показывается

- Только виды, которые **размещены на листах**. Виды, не вынесенные ни на один лист, в таблице не появляются.
- Графики тоже учитываются: Revit в `GetAllPlacedViews()` их не возвращает, плагин собирает отдельно.
- **Ведомость изменений и спецификации исключены** — у них нет номеров видов, только мешают.
- Виды-шаблоны (View Templates) в списке листов не учитываются.

### Почему ведомость изменений и спецификация отсекаются по имени

В публичном API Revit нет типов `RevisionSchedule` и `MultiCategorySchedule`,
все графики имеют `ViewType.Schedule` — отличить их по типу невозможно.
Поэтому плагин сверяет **имя вида** с набором фрагментов
(`ExcludedViewNameParts` в `SheetMapReader.cs`):

```csharp
"ведомость измен",   // Ведомость изменений
"revision schedule", // Ведомость изменений (English UI)
"специфика",         // Спецификация
"multi-category",    // Multi-Category Schedule
"multicategory"
```

Если вы переименовали эти виды или нужен другой состав — правьте этот список.

## 5. Что где менять

### Добавить колонку в таблицу

`src\Shared\SheetMapModel.cs` — добавьте свойство в класс `SheetMapRow`,
затем в `src\Shared\SheetMapPane.cs` добавьте колонку:

```csharp
_grid.Columns.Add(StarColumn("Новая колонка", "MyProperty", 1));
```

Значение вычисляйте в `SheetMapReader.Read()`.

### Изменить заголовки или ширины колонок

`src\Shared\SheetMapPane.cs`, метод `SheetMapPane()`:

```csharp
_grid.Columns.Add(FixedColumn("№ вида", "ViewNumber", 90));          // фиксированная ширина
_grid.Columns.Add(StarColumn("Название вида", "ViewName", 2));        // 2 «доли» свободного места
```

### Добавить версию Revit (например, 2024)

1. Скопируйте `src\Revit2023` в `src\Revit2024`.
2. В новом `.csproj` поменяйте `<AssemblyName>SheetViewsMap2023</AssemblyName>`
   на `SheetViewsMap2024` и `<RevitVersion ...>2023</RevitVersion>` на `2024`.
3. В `build.cmd` допишите `2024` в строку `set "VERSIONS=2021 2022 2023"`.
4. Запустите `build.cmd` после установки Revit 2024.

### Добавить ещё кнопку на ленте

1. В `Ribbon.cs` добавьте класс команды. **Обязательно** с двумя атрибутами:

```csharp
[Transaction(TransactionMode.Manual)]
[Regeneration(RegenerationOption.Manual)]
public class MyCommand : IExternalCommand
{
    public Result Execute(ExternalCommandData data, ref string message, ElementSet elements)
    {
        return Result.Succeeded;
    }
}
```

Без `using Autodesk.Revit.Attributes;` и этих атрибутов Revit **вообще не запустит
команду** и покажет окно «Невозможно запустить надстройку ... так как она не присвоена
транзакции Transaction». Код команды при этом даже не вызывается.

2. Зарегистрируйте кнопку в `Ribbon.Create()`.

### Другой язык интерфейса Revit

Номер вида в Revit API не имеет `BuiltInParameter` — его приходится искать
**по имени параметра**, а имя зависит от языка Revit.
Русское — `Номер вида`, английское — `View Number`.
Если ваш Revit на другом языке, допишите имя в массив `ViewNumberNames`
в начале `SheetMapReader.cs`.

## 6. Отладка

Плагин работает **внутри процесса Revit**, поэтому просто поставить точку
останова в VSCode не получится: нужно подключиться к уже запущенному процессу.

Варианты:

- **Visual Studio 2022** (надёжнее всего): открыть `src\Revit2023\SheetViewsMap2023.csproj`,
  в свойствах проекта указать внешнюю программу запуска
  `C:\Program Files\Autodesk\Revit 2023\Revit.exe`, поставить точки останова,
  нажать F5. Работает классический отладчик.
- **VSCode + расширение .NET**: запустить Revit вручную и подцепиться к процессу
  (`dotnet attach` / расширение C#). Работает хуже, но иногда достаточно.

## 7. Если что-то пошло не так

**Revit при загрузке ругается на плагин**
Откройте `%APPDATA%\Autodesk\Revit\Addins\<год>\SheetViewsMap.addin`.
Проверьте, что файл по пути `<Assembly>` существует и называется точно так же,
как указано. Чаще всего помогает просто пересобрать `build.cmd`.

### После каждой пересборки Revit спрашивает про подпись

Плагин не подписан сертификатом Autodesk, поэтому при загрузке Revit
показывает окно **«Безопасность — Надстройка без подписи»**:

> Невозможно проверить разработчика этой надстройки.
> Имя: SheetViewsMap, Разработчик: Неизвестный разработчик

Кнопка по умолчанию — **«Не загружать»**, поэтому плагин молча не загрузится.
Нажмите **«Всегда загружать»**.

Это нормально для любого самописного плагина: без подписи Autodesk Revit
обязан спросить. Диалог появляется и в журнале:

```
TaskDialog_Security_Unsigned_File_Loading
```

Если окно висит и ничего не происходит — Revit просто ждёт ответа
и не грузит аддины. Закройте его и запустите Revit заново.

**Вкладка «Sheet Views Map» пропала, плагин есть в папке, но Revit его не видит**
Revit кэширует список аддинов при старте. Если он падал при запуске
(например, из-за ошибки лицензирования — в журнале видно `Adlsdk Error`),
список может записаться неполным, и плагин пропустится без всякой ошибки.
**Полностью закройте Revit и запустите заново** — этого достаточно.

**Окно не открывается / Revit ругается на плагин**
Посмотрите Revit → Управление → «Внешние модули» (External Modules):
плагин должен быть в списке со статусом «Загружен» (Loaded).
Если там ошибка — нажмите «Информация», Revit покажет причину.

**Изменения в коде не видны в Revit**
DLL копируется в `%LOCALAPPDATA%\SheetViewsMap\<год>\` — убедитесь, что
смотрите именно на этот файл. **Revit надо закрыть**: открытый Revit держит
DLL, и Windows не даёт её перезаписать. Скрипт `build.cmd` предупредит об
этом в начале и проверит результат копирования.

**Окно открылось не там, где хотелось**
Удалите файл `%LOCALAPPDATA%\SheetViewsMap\window.ini` — окно откроется
по центру окна Revit, и запомнит новое положение.

**Панель есть, но написано «Нет открытого документа»**
Откройте проект `.rvt` (не семейство `.rfa`) и нажмите «Обновить».

**Номера видов пустые**
См. раздел 5, пункт «Другой язык интерфейса Revit».

**Изменения в коде не видны в Revit**
DLL копируется в `%LOCALAPPDATA%\SheetViewsMap\<год>\` — убедитесь, что
смотрите именно на этот файл, и перезапустите Revit (панель не перечитывает
DLL на лету).

## 8. Как это устроено внутри (коротко)

Главная особенность Revit API: **к нему нельзя обращаться из обычного кода интерфейса**.
Панель — это обычный WPF-элемент, обращаться к модели Revit из неё напрямую
запрещено.

Поэтому сделано так:

```
Revit
   └─► App.OnStartup
         ├─ Bridge.Initialize      ────► готовятся ExternalEvent'ы
         └─ CreateRibbonTab/Panel ────► вкладка «Sheet Views Map» на ленте

щелчок по кнопке на ленте
   └─► PaneCommand.Execute ───────────► SheetMapWindow.Toggle()
                                          ├─ окно поверх всего (TopMost)
                                          ├─ положение из window.ini
                                          └─ содержимое: SheetMapPane

кнопка «Обновить» в окне
   └─► Bridge.RequestRefresh  ────────► ExternalEvent.Raise()
                                               │
 Revit API                                    │  Execute(UIApplication)
   └─► SheetMapReader.Read()  ◄──────────────┘  читает листы и виды
                                               │  Bridge.PublishData()
   таймер 150 мс в окне   ◄──────────────────┘  рисует таблицу
```

`ExternalEvent` — это единственный разрешённый способ выполнить код с доступом
к Revit API «позже, когда Revit освободится». Поэтому в панели есть таймер:
он забирает готовый результат, когда тот появился.

Именно поэтому `Bridge.cs` существует отдельно: панель ничего не знает о
Revit API, а обработчики ничего не знают об интерфейсе.
